# 中转 D1 数据库（flashdrop-tus）建表与维护说明

> 用途：中转链路（链路①）的「索引本」。文件体存在 R2（`flashdrop-transfers`），但「谁发了什么、分享码/登录码对应哪个传输、文件指针」等结构化信息存在 D1。Worker 运行时只做增删改查（CRUD），**不自动建表**——表必须手动建一次。

## 1. 绑定信息（在 wrangler.toml 里）

| 项 | 值 |
|----|----|
| Worker 绑定名 | `DB`（代码里用 `env.DB` 访问） |
| 数据库名 | `flashdrop-tus` |
| database_id | `77286df6-c1d9-4274-82cb-b95c7371ccfa` |

`database_id` 已写死在 `wrangler.toml`，说明库已经建好，不用再建库，只需确认表存在。

## 2. 表结构（共 7 张表）

### transfers —— 传输元数据（9 列）
| 列 | 类型 | 说明 |
|----|------|------|
| id | TEXT 主键 | 传输 ID |
| message | TEXT | 留言（默认空串） |
| created_at | INTEGER | 创建时间戳(毫秒) |
| expires_at | INTEGER | 过期时间戳(毫秒) |
| terminated | INTEGER | 是否已终止（0/1，默认 0） |
| code | TEXT | 分享码（可空） |
| login_code | TEXT | 登录码（可空） |
| e2ee_salt | TEXT | E2EE 盐（可空） |
| e2ee_chunk_size | INTEGER | E2EE 分块大小（可空） |

### files —— 文件指针（7 列）
| 列 | 类型 | 说明 |
|----|------|------|
| id | TEXT 主键 | 文件 ID |
| transfer_id | TEXT | 所属传输 |
| filename | TEXT | 文件名 |
| relative_path | TEXT | 相对路径 |
| size | INTEGER | 字节数 |
| storage | TEXT | 存储位置标识 |
| offset | INTEGER | 偏移（默认 0） |

### codes —— 分享码反查（2 列）
| 列 | 类型 | 说明 |
|----|------|------|
| code | TEXT 主键 | 分享码 |
| transfer_id | TEXT | 对应传输 |

### login_codes —— 登录码反查（2 列）
| 列 | 类型 | 说明 |
|----|------|------|
| login_code | TEXT 主键 | 登录码 |
| transfer_id | TEXT | 对应传输 |

### quota_file —— 配额账本明细（6 列，配额系统）
| 列 | 类型 | 说明 |
|----|------|------|
| file_id | TEXT 主键 | 文件 ID（reserve 时写入） |
| account_id | TEXT | 归属桶 ID |
| transfer_id | TEXT | 所属传输 |
| size | INTEGER | 占用的字节数 |
| expires_at | INTEGER | 过期时间戳 |
| released | INTEGER | 是否已释放（0/1，默认 0） |

### quota_account —— 每桶用量汇总（3 列，配额系统）
| 列 | 类型 | 说明 |
|----|------|------|
| account_id | TEXT 主键 | 桶 ID |
| used_bytes | INTEGER | 当前未释放占用字节数 |
| updated_at | INTEGER | 更新时间戳 |

### transfer_account —— 传输→桶归属（2 列，选桶系统）
| 列 | 类型 | 说明 |
|----|------|------|
| transfer_id | TEXT 主键 | 传输 ID |
| account_id | TEXT | 该传输选中的桶 ID |

另建 3 个索引：`files(transfer_id)`、`codes(transfer_id)`、`login_codes(transfer_id)`。

> 配额/选桶三张表（quota_file / quota_account / transfer_account）在代码首次运行时自动 INSERT 建行，但**表本身需手动建一次**（见下方附录 SQL）。

## 3. 第一次怎么建（两种方式，结果完全一样）

> 两种方式任选其一，建的表完全相同。**你之前用的是「方式一：D1 控制台」**——不用装任何工具，粘贴代码点执行即可。

### 方式一：在 Cloudflare D1 控制台一键执行（推荐，你之前用的方法）
控制台默认就是线上库，不用管本地/远程。
1. 打开 Cloudflare 控制台，进入 **D1**，找到数据库 `flashdrop-tus`。
2. 点进该数据库，切到 **控制台（Console）** 标签，下面有一个 SQL 代码输入框。
3. 把下方「附录 SQL」整段**粘贴**进输入框。
4. 点 **执行 / Run**，几秒后提示成功，7 张表就建好了。

> 这就是你之前用的办法：我给你那段代码 → 你粘贴进控制台输入框 → 点执行 → 表建完。

### 方式二：本地 wrangler 命令行
前提：`wrangler login` 已登录；`wrangler` 已装（`npm i -g wrangler`）。

#### 步骤 A：确认数据库已存在（已有则跳过）
`wrangler.toml` 已写死 `database_id`，说明库已建好，跳过本步。
若要从头新建库：
```bash
wrangler d1 create flashdrop-tus
```
把回显的 id 填进 `wrangler.toml` 的 `database_id`。

#### 步骤 B：在【线上】库执行建表 SQL
**关键**：用 `--remote` 打到生产库，不要用 `--local`（`--local` 是本地临时库，线上读不到）。

把下方「附录 SQL」整段存成 `schema.sql`（和 `wrangler.toml` 同目录），然后执行：
```bash
wrangler d1 execute flashdrop-tus --remote --file=./schema.sql
```

或不想存文件，直接贴命令（SQL 较长，推荐用上面的 `--file` 方式）：
```bash
wrangler d1 execute flashdrop-tus --remote --command="CREATE TABLE IF NOT EXISTS transfers (id TEXT PRIMARY KEY, message TEXT NOT NULL DEFAULT '', created_at INTEGER NOT NULL, expires_at INTEGER NOT NULL, terminated INTEGER NOT NULL DEFAULT 0, code TEXT, login_code TEXT, e2ee_salt TEXT, e2ee_chunk_size INTEGER); CREATE TABLE IF NOT EXISTS files (id TEXT PRIMARY KEY, transfer_id TEXT NOT NULL, filename TEXT NOT NULL, relative_path TEXT NOT NULL, size INTEGER NOT NULL, storage TEXT NOT NULL, offset INTEGER NOT NULL DEFAULT 0); CREATE TABLE IF NOT EXISTS codes (code TEXT PRIMARY KEY, transfer_id TEXT NOT NULL); CREATE TABLE IF NOT EXISTS login_codes (login_code TEXT PRIMARY KEY, transfer_id TEXT NOT NULL); CREATE INDEX IF NOT EXISTS idx_files_transfer ON files(transfer_id); CREATE INDEX IF NOT EXISTS idx_codes_transfer ON codes(transfer_id); CREATE INDEX IF NOT EXISTS idx_login_transfer ON login_codes(transfer_id);"
```

`IF NOT EXISTS` 保证幂等：重复执行不会报错（已有表则跳过）。

## 4. 以后维护
- 表建好后，日常只有增删改，不用再跑建表。
- 真要重建（换库/换环境）：先 `wrangler d1 create` 拿新 id → 改 `wrangler.toml` 的 `database_id` → 跑步骤 B。
- 建表 SQL 权威来源：本目录 `schema.sql`（下方附录也完整贴出一份，可直接粘贴进控制台输入框或 `wrangler d1 execute ... --file=./schema.sql` 执行）。

## 附录：完整建表 SQL（直接粘贴进控制台输入框 / 存成 schema.sql 的代码）
```sql
CREATE TABLE IF NOT EXISTS transfers (
  id             TEXT PRIMARY KEY,
  message        TEXT NOT NULL DEFAULT '',
  created_at     INTEGER NOT NULL,
  expires_at     INTEGER NOT NULL,
  terminated     INTEGER NOT NULL DEFAULT 0,
  code           TEXT,
  login_code     TEXT,
  e2ee_salt      TEXT,
  e2ee_chunk_size INTEGER
);
CREATE TABLE IF NOT EXISTS files (
  id           TEXT PRIMARY KEY,
  transfer_id  TEXT NOT NULL,
  filename     TEXT NOT NULL,
  relative_path TEXT NOT NULL,
  size         INTEGER NOT NULL,
  storage      TEXT NOT NULL,
  offset       INTEGER NOT NULL DEFAULT 0
);
CREATE TABLE IF NOT EXISTS codes (
  code        TEXT PRIMARY KEY,
  transfer_id TEXT NOT NULL
);
CREATE TABLE IF NOT EXISTS login_codes (
  login_code   TEXT PRIMARY KEY,
  transfer_id  TEXT NOT NULL
);
CREATE TABLE IF NOT EXISTS quota_file (
  file_id     TEXT PRIMARY KEY,
  account_id  TEXT NOT NULL,
  transfer_id TEXT NOT NULL,
  size        INTEGER NOT NULL,
  expires_at  INTEGER NOT NULL,
  released    INTEGER NOT NULL DEFAULT 0
);
CREATE TABLE IF NOT EXISTS quota_account (
  account_id  TEXT PRIMARY KEY,
  used_bytes  INTEGER NOT NULL DEFAULT 0,
  updated_at  INTEGER NOT NULL DEFAULT 0
);
CREATE TABLE IF NOT EXISTS transfer_account (
  transfer_id TEXT PRIMARY KEY,
  account_id  TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_files_transfer   ON files(transfer_id);
CREATE INDEX IF NOT EXISTS idx_codes_transfer    ON codes(transfer_id);
CREATE INDEX IF NOT EXISTS idx_login_transfer    ON login_codes(transfer_id);
CREATE INDEX IF NOT EXISTS idx_qf_acct           ON quota_file(account_id, released, expires_at);
```
