# ArkPulse 中转 Worker（conduit-tus）R2 / S3 凭证与密钥说明

> 备忘文档。记录中转 Worker 用到的几个「S3 相关密钥」到底是什么、当前值、怎么获取、放在哪。
> 适用对象：flashdrop-tus Worker（文件体存 R2、索引用 D1）。

---

## 1. 这些密钥的本质是什么

Cloudflare **R2 的 S3 兼容 API 令牌**。

中转 Worker 用 `aws4fetch`（`AwsClient.sign(..., {signQuery:true})`）按 **S3 签名协议** 生成「预签名 URL」，
让浏览器**绕过 Worker 直接读写 R2**（上传 PUT / 下载 GET），避免大请求体经 Worker 流式透传导致的字节损坏。

所以这三个变量不是 CloudFlare 账户密码，而是「R2 存储桶的编程访问令牌」——
作用范围 = `flashdrop-transfers` 桶的对象读写（Object Read & Write）。

```
变量 → aws4fetch 签名 → https://<桶>.<账户ID>.r2.cloudflarestorage.com/<key>
```

## 2. 三个变量一览

| 变量名 | 当前值 | 是什么 | 敏感？ | 在代码哪用 |
|--------|--------|--------|--------|-----------|
| `R2_ACCOUNT_ID` | `da94b5e41f7c56ff2df7043718a53616` | Cloudflare **账户 ID**（S3 端点主机名的一部分） | 否（公开信息） | `r2-storage.ts` 拼域名、`factory.ts` 读 env |
| `R2_ACCESS_KEY_ID` | `39305e4d3cbf6f41477be63a9aa479e6` | S3 兼容 **访问密钥 ID**（AK） | 否 | `factory.ts` → `AwsClient({accessKeyId})` |
| `R2_SECRET_ACCESS_KEY` | `aaaa2c322081e2f3e0b314dddc288b51b0b5d960df7838aa405863d31d3cad` | S3 兼容 **私有访问密钥**（SK） | **是（绝不能外泄）** | `factory.ts` → `AwsClient({secretAccessKey})` |

> 三者配套，缺失任意一个 `createStorage` 会抛「未配置 R2_*，无法生成 presigned URL」。
> 桶名 `flashdrop-transfers` 与 `accountId` 一起拼成 `{bucket}.{accountId}.r2.cloudflarestorage.com`，
> 桶名**不是**环境变量，硬编码在 `factory.ts` / `r2-storage.ts`（`bucketName: 'flashdrop-transfers'`）。

### 关联的另外两个绑定（不是密钥，但同属部署配置）
- `[[r2_buckets]]` → `R2_TRANSFERS` binding 指向桶 `flashdrop-transfers`（Worker 原生 R2Bucket，用于流式 put/get/delete/list，与 presigned 互补）
- `[[d1_databases]]` → `DB` binding，库名 `flashdrop-tus`，`database_id = 77286df6-c1d9-4274-82cb-b95c7371ccfa`

## 3. 怎么获取（创建新令牌 / 轮换）

> 路径以 Cloudflare Dashboard 当前 UI 为准，名称可能微调。

1. 登录 **Cloudflare Dashboard** → 左侧进入 **R2 对象存储（R2 Object Storage）**。
2. 右上角 / 侧栏找到 **「管理 API 令牌（Manage API Tokens）」或「账户 API 凭据」**。
3. 点 **「创建 API 令牌（Create API Token）」**：
   - **权限（Permissions）**：`Object Read & Write`（仅对象读写，最小权限）
   - **适用对象（Scope）**：选 `flashdrop-transfers` 桶（或账户级 Account 类型）
4. 创建后页面会显示：
   - **Access Key ID**（可重复查看）
   - **Secret Access Key**（**只显示这一次**，必须立刻复制保存；关页面后看不到）
5. **账户 ID**：Dashboard 任意页面右侧栏「账户 ID（Account ID）」复制。

把这三段分别填进下面第 4 节的对应变量即可。

## 4. 放在什么部位（关键）

**当前位置**：`conduit-tus/wrangler.toml` 的 `[vars]` 段（第 18–25 行）：

```toml
[vars]
DEFAULT_TTL_HOURS = "24"
R2_ACCOUNT_ID = "da94b5e41f7c56ff2df7043718a53616"
R2_ACCESS_KEY_ID = "39305e4d3cbf6f41477be63a9aa479e6"
R2_SECRET_ACCESS_KEY = "aaaa2c322081e2f3e0b314dddc288b51b0b5d960df7838aa405863d31d3cad"
```

### 为什么放 `[vars]` 而不是 Dashboard 手填
本项目 `conduit-tus` 随 `git push main` **自动部署**。
实测坑：通过自动部署上线的 Worker，**不保证挂载 Dashboard「Variables and Secrets」手填的变量**（Cloudflare 已知行为）。
而 `wrangler.toml` 的 `[vars]` 是自动部署必定带上的配置 —— 所以凭证必须写在这里才能稳定生效。

### 正确姿势（安全建议）
`R2_SECRET_ACCESS_KEY` 是敏感值，明文进 git 仓库是隐患。推荐两种处理：

- **方案甲（推荐）**：敏感 SK 走 `wrangler secret`
  ```bash
  wrangler secret put R2_SECRET_ACCESS_KEY --config conduit-tus/wrangler.toml
  ```
  然后 `wrangler.toml` 里删掉那行明文 SK（secret 会覆盖同名的 `[vars]`）。
  AK 和 Account ID 非敏感，留 `[vars]` 即可。
- **方案乙（现状）**：三者全放 `[vars]` 明文，靠 git 仓库私有性兜底；上线稳定后应轮换令牌并迁移到方案甲。

### 轮换顺序（极易踩坑）
去 R2 令牌页「删旧建新」后，**必须同步**更新 `wrangler.toml [vars]` 的三个值再 `git push`。
顺序错（只建新令牌、忘了更新 Worker 侧值）会立刻 `500` / `403`（Worker 用死令牌签 URL → 浏览器 PUT/GET 被 R2 拒）。

## 5. 常见坑（血泪记录）

1. **Secret 粘贴漏字符**：曾把 `...b51b0b0b5d960` 抄成 `...b51b0b5d960`（少一个 `b0`），导致所有 presigned 请求 `403 Forbidden`，误判成「令牌被吊销 / 网络慢」。
   → 比对必须用 `diff` 逐字符，不要肉眼抄。
2. **自动部署不挂 Dashboard 变量**：见第 4 节，凭证只在 `wrangler.toml [vars]` 或 `wrangler secret` 才稳。
3. **boto3 误判令牌失效**：R2 S3 令牌 `list_buckets` 返回 `AccessDenied` 是**常态**（无账号级权限），
   要用 `head_bucket('flashdrop-transfers')` + `put_object` 是否 `OK` 判定令牌对桶是否有效。
4. **CORS 与密钥无关但常一起出错**：浏览器直连 R2 预签名 URL 还需桶 CORS 放行前端源（见下文）。

## 6. R2 桶 CORS（与密钥配套，但非密钥本身）

### 6.1 这套配置是干什么的

浏览器**跨域**直连 `*.r2.cloudflarestorage.com` 存/取数据，R2 桶必须 CORS 放行前端源。
否则浏览器即使拿着合法的 presigned URL，也会在 console 报 `CORS` 红错（`Access-Control-Allow-Origin` 缺失），请求被拦。

**CORS 和签名是两回事**：签名管"你能不能访问这个对象"，CORS 管"浏览器能不能跨域读这个响应"。两者都得过。

### 6.2 当前上线生效的实际策略（2026-08 核对）

```json
[
  {
    "AllowedOrigins": [
      "https://flashdrop.pages.dev",
      "https://*.flashdrop.pages.dev"
    ],
    "AllowedMethods": [
      "PUT",
      "GET",
      "HEAD"
    ],
    "AllowedHeaders": [
      "*"
    ],
    "MaxAgeSeconds": 86400
  }
]
```

### 6.3 每个字段干什么 / 怎么写

| 字段 | 值 | 含义 / 怎么写 |
|------|----|-------------|
| `AllowedOrigins` | `https://flashdrop.pages.dev` + `https://*.flashdrop.pages.dev` | 允许跨域请求的**前端来源**。主站 + preview 部署（`*` 通配子域）。本地调试若要直连 R2 可补 `http://localhost:5173`、`http://127.0.0.1:5173`（当前未列，因线上用不到；列了本地 dev 也会直连成功）。 |
| `AllowedMethods` | `PUT` `GET` `HEAD` | 允许跨域发起的 **HTTP 方法**。`PUT`=上传直连；`GET`=下载直连（方案 A）；`HEAD`=对象探测/预检。 |
| `AllowedHeaders` | `*` | 允许请求带**任意头**。下载续传的 `Range` 头、上传的 `Content-Type` 等均被放行（`*` 最省事）。 |
| `MaxAgeSeconds` | `86400` | 预检（`OPTIONS`）响应缓存 **24 小时**。期内同源跨域请求不再发 OPTIONS 预检，省一次往返。 |

> 数组包一层 `[]` 是因为 R2 CORS **支持多条策略**（不同源组各写一条）。当前只有一条，全站共用。

### 6.4 上传 vs 下载对比（这套配置够不够）

| 链路 | 用的预签名 | 需要的方法 / 头 | 配置是否满足 |
|------|-----------|----------------|-------------|
| **上传**（PUT 直连） | presigned `PUT` | `PUT` + Origin=Pages | ✅ `AllowedMethods` 含 `PUT`，`AllowedOrigins` 含 Pages | 已验证（2.1GB 秒传） |
| **下载**（GET 直连，方案 A） | presigned `GET` + `Range` | `GET` + Origin=Pages + `Range` 头 | ✅ `AllowedMethods` 含 `GET`，`AllowedHeaders: *` 含 `Range` | 配置已含 `GET`，**方案 A 下载直连无需再改 CORS** |

**结论**：这份 CORS **同时覆盖上传和下载**。之前文档写的「必须把 GET 加入 AllowedMethods」是基于推测，
实际你这份已上线配置里 `GET` 已在 `AllowedMethods` 中，方案 A 落地后**不用补任何 CORS 改动**。

### 6.5 怎么部署 / 修改这套配置

两种方式（任选其一）：

- **Dashboard**：R2 → `flashdrop-transfers` → Settings → CORS → 粘贴 / 编辑 JSON 保存。
- **命令行**：把上面 JSON 存成 `cors.json`，执行
  ```bash
  wrangler r2 bucket cors put flashdrop-transfers --config conduit-tus/wrangler.toml --file cors.json
  ```

### 6.6 注意点（诚实标注）

- 实际配置**未列** `ExposeHeaders`。前端下载走 `Range`，依赖的 `Content-Range` / `Content-Length` 属 CORS 安全列表头，自动暴露，无需显式 `ExposeHeaders`。当前无影响。
- `AllowedHeaders: *` 较宽松，但配合 presigned URL（URL 本身带签名、限定 object key + 方法 + 过期），风险可控。若以后要收紧，可改成 `["Range","Content-Type","Origin"]`。

---

## 7. 一句话总结

三个变量 = R2 的 S3 兼容令牌（账户ID + 访问密钥ID + 私有密钥），写在 `conduit-tus/wrangler.toml [vars]`，
用于 aws4fetch 签预签名 URL 让浏览器直连 R2；敏感 SK 建议迁 `wrangler secret`，轮换必须同步三值并推送。
